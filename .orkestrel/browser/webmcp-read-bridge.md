# bridge

## summary

@orkestrel/mcp 0.0.33 ships a complete, tested WebMCP bridge under its ESM-only `./browser` face: `createModelContext` (feature detection by return value, no polyfill), the `ModelContext` class with `emitter`, `publish`, `adopt`, `destroy`, the `WebMCP*` types transliterated from the WebIDL as read 2026-09-15, a three-hint annotation mapping in both directions, and a guide section titled "## WebMCP parity" with 18 verdict rows. The bridge subscribes to the registry's `toolchange` only and names none of the spec's `toolactivated`, `toolcancel`, or `debugging` members that the page fetched 2026-09-29 declares. Every bridge scenario runs in real Chromium against `tests/fixtures/modelContext.ts`, an in-memory `EventTarget` subclass implementing the IDL member for member; a native block is gated by `describe.runIf(isWebMCPDocument(document))` and collects on no shipping browser. Nothing named "adapter" touches WebMCP; "conformance" in mcp means the `@modelcontextprotocol/conformance` MCP-wire runner only, and README and guide disagree on its numbers.
