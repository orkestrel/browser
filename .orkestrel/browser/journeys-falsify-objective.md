The proposal is not ready for implementation. The verdicts below assess its written algorithms and contracts. Historical probes support specific findings; they do not prove the proposed journey implementation.

1. **BROKEN — Complete action-event coverage.** A pre-aborted `tools.execute(click, context)` returns a refusal before invoking the tool, so an event emitted inside `BrowserToolset` cannot cover every refused call. The installed manager also passes only arguments and context to the handler; the proposed `BrowserActionRecord` has no invocation identity for distinguishing an inner replay call from a concurrent refused call. See [the installed manager](/home/user/browser/node_modules/@orkestrel/tool/dist/src/core/index.js:260), [the installed call contract](/home/user/browser/node_modules/@orkestrel/tool/dist/src/core/index.d.ts:155), and [the proposed event](/home/user/browser/tmp/units/journeys/design-reconciled.md:102). **Correction:** define correlated coverage for calls admitted to the toolset, explicitly handle manager-level refusals in replay, and subscribe before dispatch. Target facts must be optional when refusal precedes target resolution.

2. **UNRESOLVED — Exact queries and frame scoping.** Attack with `Save`, `Save draft`, whitespace variants, and identical names in separate frames. The shared filter performs case-insensitive substring matching; neither query contract defines `exact` or `frame`, and the CDP CSS implementation selects the main document. The proposal does not decide exact-match case sensitivity or how a DOM placement identifies frames. See [the filter](/home/user/browser/src/core/helpers.ts:102), [the query contract](/home/user/browser/src/core/types.ts:1778), and [CSS resolution](/home/user/browser/src/core/elements/BrowserElementManager.ts:139). **Settlement:** specify normalization and frame identity, then prove exact/default matching and frame-scoped role/CSS queries independently in both placements.

3. **BROKEN — Duplicate-name refusal.** Record `e7 button "Delete"`, retain that element, then add another `button "Delete"`. The reference-first branch accepts `e7` without counting semantic matches. It also omits the target’s frame constraint. A reference from another context can coincidentally have the same spelling and description. See [the resolution ladder](/home/user/browser/tmp/units/journeys/design-reconciled.md:117) and [reference lifetime](/home/user/browser/guides/browser.md:2509). **Correction:** resolve fresh semantic candidates within scope before accepting a reference. Keep persisted references as evidence, not a bypass around ambiguity.

4. **BROKEN — CSS-only ambiguity coverage.** The mismatch refusal is sound, but a CSS-only target cannot satisfy `BrowserJourneyTarget`: `role` and `name` are mandatory. A test supplying only `{ css: '.purchase' }` can fail validation without ever exercising CSS ambiguity, producing a vacuous proof. See [the target type](/home/user/browser/tmp/units/journeys/design-reconciled.md:24) and [claim 4](/home/user/browser/tmp/units/journeys/design-reconciled.md:235). **Correction:** admit an explicit CSS-only target shape or remove that capability from the claim. Its ambiguity test must establish that the resolver reached both candidates and dispatched no input.

5. **BROKEN — Direct-call equivalence, especially dialogs.** A journey containing `click` followed by `dialog` is rejected during preparation when no dialog is initially open. Direct calls succeed because the click stages the dialog tool. The same problem affects an adopted tool registered only after navigation. See [preparation](/home/user/browser/tmp/units/journeys/design-reconciled.md:112) and [dynamic dialog publication](/home/user/browser/src/core/BrowserToolset.ts:1295). The proposal also lacks a dialog-continuation outcome distinguishing interrupted input from completed input. **Correction:** distinguish backend capability from present advertisement, revalidate dynamic availability when reached, and define the matching dialog continuation while preserving the pending-input barrier. Supply the required call `id` and separate execution context when invoking the manager.

6. **UNRESOLVED — Replay exclusion and release.** Attack this ordering: foreign action A is active; foreign action B has already joined the queue; replay acquires its hold; replay dispatches its first inner action. An admission-only busy flag lets B execute during replay. Holding the existing queue while recursively calling its tools can instead deadlock. Neither ownership mechanism nor acquisition ordering is specified. See [the proposed hold](/home/user/browser/tmp/units/journeys/design-reconciled.md:113), [queue acquisition](/home/user/browser/src/core/BrowserToolset.ts:859), and [pending-command retention](/home/user/browser/src/core/BrowserToolset.ts:977). **Settlement:** define an opaque replay owner, atomic admission, treatment of previously admitted work, and release in `finally`. Prove abort during acquisition, input release, dialog interruption, capture, and persistence without permitting a following action past unfinished input.

7. **CONFIRMED — Structured wait classification is the correct design rule.** The attack is a wait returning transport success while its expected text never appears. That attack fails against the proposal’s explicit outcome rule: replay must stop despite the successful transport envelope. The existing timeout branch supplies a structured decision point without changing its sentence. See [the timeout branch](/home/user/browser/src/core/BrowserToolset.ts:707), [the v8 counterexample](/home/user/ollama/tmp/probes/logs/v8/click-1.json:210), and [the proposed classification](/home/user/browser/tmp/units/journeys/design-reconciled.md:124). The implementation proof must mutate the timeout outcome to `done` and assert that an otherwise unexecuted suffix would then run.

8. **CONFIRMED — Whole-document preparation defeats the enumerated static refusals.** Place a valid consequential click before a step with a missing binding, unknown supplied input, incompatible input format, `unresolved` tool, or unknown tool. The specified preparation examines the journey before entering the execution loop, so none permits that click. See [preparation and execution ordering](/home/user/browser/tmp/units/journeys/design-reconciled.md:112). The stated event-counter instrument distinguishes moving validation into the per-step loop: the first click would increment the counter. This confirmation covers those static checks; it does not establish the broader DOM refusal promise discussed in O3.

9. **UNRESOLVED — Atomic editing and revision concurrency.** Copying and rejecting an invalid batch is a coherent pure-edit rule. The storage guarantee remains unspecified: two store instances can both read revision R, both compare successfully, and each rename a revision R+1 over the same destination if serialization belongs only to an instance. See [editing](/home/user/browser/tmp/units/journeys/design-reconciled.md:164) and [per-name serialization](/home/user/browser/tmp/units/journeys/design-reconciled.md:241). **Settlement:** define the lock’s scope and keep read, comparison, revision assignment, and publication inside it. Exercise separate instances and processes over the same directory. Moving the comparison outside the critical section must fail the test.

10. **UNRESOLVED — Filesystem store conformance.** A sibling temporary file and rename describe replacement, but not temporary-file exclusivity, cross-instance coordination, cancellation around publication, cleanup after failure, or the listing order. No implemented store or conformance result is supplied. See [claim 10](/home/user/browser/tmp/units/journeys/design-reconciled.md:241). **Settlement:** run the shared suite against real disk and memory implementations, including reopening, malformed JSON, missing/unknown `format`, permission errors, concurrent publication, and stable paging. Assert that corruption differs from absence and that a failed publication preserves the previous readable revision. A mutation collapsing corruption to `undefined` must fail.

11. **BROKEN — Page gestures fit the recorded tool vocabulary.** A native multiple select changing to `['red', 'blue']` must become `type` “with the values,” but the existing tool accepts one string `text` and calls `element.select([text])`. The proposal mentions `select` bindings while excluding `select` from its native recorded tools. See [recording](/home/user/browser/tmp/units/journeys/design-reconciled.md:103), [the binding invariant](/home/user/browser/tmp/units/journeys/design-reconciled.md:80), [the tool schema](/home/user/browser/guides/browser.md:2390), and [selection execution](/home/user/browser/src/core/BrowserToolset.ts:822). **Correction:** extend the shared tool contract to represent complete selections, or record this gesture as unresolved. The independent event log must also distinguish Enter activation from its resulting click, and verify flushing at submission, focus departure, navigation, and stop.

12. **BROKEN — Secret exclusion.** Replay substitutes a protected string into the ordinary `type` arguments. That handler immediately embeds the string in its receipt, before any recorder or run renderer can replace it. The proposed dispatch carries no secret metadata. The retained page listener likewise sends password values through the runtime binding. See [replay dispatch](/home/user/browser/tmp/units/journeys/design-reconciled.md:114), [receipt construction](/home/user/browser/src/core/BrowserToolset.ts:522), and [password recording](/home/user/browser/src/core/constants.ts:303). **Correction:** establish protection before event serialization and receipt construction, and carry protected-field metadata through execution. Cover arguments, defaults, targets, error messages, receipt views, output, and captures. Generated code must retain a required binding without embedding the supplied value. Bound the claim explicitly where arbitrary page output transforms or republishes a secret.

13. **BROKEN — Generated-module equivalence.** The displayed module calls `element.type(..., { submit: true })`, which the public element contract does not expose. It also ignores settlement results, omits submission destinations, records the main frame rather than the resolved element’s frame, and lacks `finally` cleanup. `settle()` can return immediately when no navigation has started and no destinations were supplied; C6 records navigation beginning after input replies. See [the generated module](/home/user/browser/tmp/units/journeys/design-reconciled.md:173), [public element operations](/home/user/browser/src/core/types.ts:1905), [settlement semantics](/home/user/browser/src/core/BrowserNavigationRecord.ts:132), and [C6 ordering evidence](/home/user/browser/.orkestrel/browser/c6-probe-report.md:84). Comment-only placeholders additionally permit the generated module to continue past an omitted consequential step. **Correction:** retain readable public calls, but generate the actual fill/select/submit and settlement protocol, reject incomplete settlement, and refuse unsupported compilation or emit an unconditional failure. Test delayed submissions, child frames, popups, and unsupported steps; a fast final-state fixture alone cannot settle equivalence.

14. **UNRESOLVED — Packed binary and lifecycle.** Attack discovery with Chromium unavailable, then EOF during lazy construction and SIGTERM during replay. The proposed server has no defined bootstrap registry before its page-dependent toolset exists. Probe supplies useful lazy-construction ownership, but its stdin-close handler only ends the transport stream; copying that handler does not establish browser destruction. See [the binary proposal](/home/user/browser/tmp/units/journeys/design-reconciled.md:208) and [probe’s lifecycle](/home/user/orkestrel/probe/src/server/ProbeServer.ts:118). **Settlement:** choose the package, define discovery and teardown ownership, and drive the packed artifact with the real stdio client. Assert child termination and filesystem destinations after each exit path. Also resolve the unparsed `--port` option promised by an otherwise command-free binary.

15. **UNRESOLVED — Small-model journey usability.** The supplied v5–v10 runs exercise ordinary browser tools, not the proposed journey listing, binding object, or edit array. They establish neither successful journey use nor superiority over an operation-discriminated tool. The required-parameter evidence concerns the streamed parser, not that comparison. See [the guide’s parser finding](/home/user/browser/guides/browser.md:2383), [the proposal’s inference](/home/user/browser/tmp/units/journeys/design-reconciled.md:206), and [the v10 reading](/home/user/browser/.orkestrel/browser/ledger.md:371). **Settlement:** run the proposed tools with the stated model, preserving page/file oracles and recording attempts, incorrect actions, and tool-list cost. Include removal of a duplicate submission; v10’s form state contains duplicate orders, so a recording cannot be assumed to express the intended flow.

Findings on the rulings and shape follow.

- **O1 — Blocking: inline bindings collide with valid literal arguments.** An adopted tool can legitimately accept `{ payload: { input: 'customer' } }` as literal data. `BrowserJourneyBinding<unknown>` cannot distinguish that object from a binding, and the union supplies no TypeScript restriction because `unknown` already includes it. It also admits values that cannot satisfy the claimed JSON round trip. See [the binding and arguments types](/home/user/browser/tmp/units/journeys/design-reconciled.md:15). **Smallest correction:** keep declared inputs, but provide an unambiguous literal representation or separate binding locations. Define the JSON-safe value domain and binding traversal. A discriminated input declaration must couple `format` to its default’s shape. Declared inputs remain useful; their presence does not solve literal ambiguity.

- **O2 — Required: edit transport and batch validation are incomplete.** Removing an input uses a required property whose value is `undefined`; JSON serialization drops that property. Moreover, adding a declaration and then adding its first binding temporarily violates “every declared name is bound,” while reversing those edits temporarily violates “every bound name is declared.” See [edit types](/home/user/browser/tmp/units/journeys/design-reconciled.md:61), [the invariant](/home/user/browser/tmp/units/journeys/design-reconciled.md:70), and [atomic editing](/home/user/browser/tmp/units/journeys/design-reconciled.md:164). **Smallest correction:** define an explicit JSON representation for input removal, validate edit-local structure while applying the batch, and validate cross-step binding invariants on the final candidate. Test declaration-plus-binding addition and removal in one batch.

- **O3 — Blocking: persisted frame/tab identities and blanket DOM preflight are not portable.** Reopening the same site gives its frames different protocol ids. Reordering open pages changes what recorded `switch { tab: 't2' }` selects. Neither has a semantic identity in the journey. See [the persisted frame](/home/user/browser/tmp/units/journeys/design-reconciled.md:30), [switch execution](/home/user/browser/src/core/BrowserToolset.ts:764), and [the deferred boundaries](/home/user/browser/tmp/units/journeys/design-reconciled.md:273). See [DOM contenteditable refusal](/home/user/browser/src/browser/elements/BrowserDOMElement.ts:79). **Smallest correction:** define portable frame/page locators or explicitly refuse these recordings across sessions. Limit preparation guarantees to statically decidable capabilities; preserve the executed prefix for live-target refusals. Deferring region and shadow addressing is acceptable only when unsupported ambiguity refuses without widening scope.

- **O4 — Blocking: path containment and run uniqueness have no enforcing algorithm.** A valid journey name can name a symlinked directory outside the root; the same applies to `runs` or a capture destination. The name pattern also admits `con`, contrary to the cross-host filename rule. Two producers can mint identical timestamp-plus-four-hex identifiers, and no exclusive run-directory creation or collision rule is specified. See [the layout and pattern](/home/user/browser/tmp/units/journeys/design-reconciled.md:77), [run-id generation](/home/user/browser/tmp/units/journeys/design-reconciled.md:160), and [path rules](/home/user/scaffold/.claude/rules/portability.md:43). **Smallest correction:** define containment for every read, temporary file, rename, compiled file, capture, and run directory; reject reserved device names; state the symlink/race boundary; allocate run directories exclusively and retry collisions. Add real-filesystem adversarial tests before assigning this work to a mechanical builder.

- **O5 — Required: persistence failure, abort evidence, and authored-run revision are undefined.** After a successful consequential click, `store.set` can fail. The replay promises to reject only on abort or destruction, but its outcome union has no persistence failure. Abort can also bypass the terminal write, while forwarding the already-aborted signal prevents that write from preserving the partial run. A directly authored journey has no store revision, although every run requires one. See [execution completion](/home/user/browser/tmp/units/journeys/design-reconciled.md:115) and [the run record](/home/user/browser/tmp/units/journeys/design-reconciled.md:146). **Smallest correction:** specify action outcome separately from artifact outcome, define bounded finalization and partial evidence, and make revision provenance represent authored journeys without a fabricated revision.

Meanwhile, `compile` writes a file and replay writes run artifacts, but `readonly` gates only recording, saving, and editing. See [the tool table and rulings](/home/user/browser/tmp/units/journeys/design-reconciled.md:195). **Smallest correction:** expose structured continuation parameters and distinguish catalogue paging from a long journey’s step paging.
